# Durableな開発判断ログの保存ルール

この文書は、コードまたは正本仕様に影響するdurableな判断と実施結果をGitへ継続保存する運用の正本である。保存先は `docs/DEVELOPMENT_THREAD_LOG.md` とする。

ログは現在仕様の正本ではない。別スレッドや別担当が「なぜその状態になったか」「何が未完了か」を見失わないための参考記録であり、実装時は `docs/README.md` から現行資料とコードを確認する。

TODOの現在地、監督判定、個別指示書・結果書、スレッドhandoffはChatGPTプロジェクト側で管理し、Gitログへ重複保存しない。

## 必須となるタイミング

次のいずれかが発生し、コードまたは正本文書へ反映する作業単位は、同じcommitでログを追記する。

- 実装する仕様、命名、数値条件が確定し、正本へ反映した。
- 長期的な設計方針、採用案、廃止方針が確定し、正本へ反映した。
- バグの根本原因または恒久的な制約が確定し、修正または既知問題の正本へ反映した。
- コード、設定、DB、Redis、Blob、Vercel、DNS、GitHub等を変更した。
- 公開方法、外部設定、migration、セキュリティ境界を変更した。

次はGitログの必須対象外とする。

- 調査・分析だけで、コード、設定、正本仕様を変更しない。
- TODO採番、進捗更新、監督判定、作業指示、結果報告、スレ移行だけを行う。
- 既に正本へ反映済みの内容を言い換える。
- local testやbuildを再実行しただけで、新しい恒久的事実がない。
- checkpoint commit、push、Deploymentのidentityと結果だけを運用記録へ残す。

## 記録単位とタイミング

- 1メッセージごとではなく、同じ目的を持つ一連の作業を1項目にまとめる。
- 原則として作業の最終報告前に追記する。
- 長時間または複数段階の作業は、重要な仕様決定、外部設定変更、公開の直後にもチェックポイントを残す。
- コードや文書をコミットする作業では、ログ追記を同じコミットに含める。
- 会話だけで決まった案は、実装対象として確定し正本文書へ反映するまではChatGPTプロジェクト側のTODO・判断記録に置く。
- Gitへ残す必要がある確定事項を保存できない場合は、`UNSAVED / AT RISK`として対象と実在場所を報告する。

## 環境変数・外部設定は二重記録する

Vercel、Neon、Upstash、Blob、DNS、GitHub権限、外部API設定を扱った場合、`DEVELOPMENT_THREAD_LOG.md` への経緯記録だけでは完了しない。

- 現在の配置、キー名、Project、対象環境、Sensitive区分、設定・Link・再デプロイ・実機確認の状態は `ENVIRONMENT_VARIABLES.md` を更新する。
- 要望、判断理由、途中の誤案内、障害、関連コミット、次回への保留は `DEVELOPMENT_THREAD_LOG.md` へ記録する。
- 設定前の予定と、画面・APIで確認した現在状態を混同しない。
- 変数を保存しただけなら「登録済み」、Shared変数を関連付けたなら「Link済み」、新Deployment作成後は「再デプロイ済み」、機能確認後だけ「実機確認済み」と書く。
- 台帳にない環境変数や外部設定を発見した場合は、その場で値を記録せず、名称と配置・状態だけを台帳へ補う。
- 秘密値を安全に記録できないことは台帳更新を省略する理由にしない。値は一切保存せず、存在と管理状態だけを残す。

## 必須項目

項目はJSTの日付と短い題名を付け、必要な見出しだけを使う。

```markdown
## YYYY-MM-DD — 題名

### 利用者からの要望

- 何を求められたか。

### 判断

- 採用した方針と、将来の担当が必要とする理由。

### 実施結果

- 実装・設定・調査で実際に完了したこと。

### 検証

- 実行したテスト、build、実機確認、デプロイ結果。

### 関連コミット

- `abcdef0` — 要約

### 未対応・保留

- 次に必要な作業、保留理由、未検証範囲。
```

少なくとも、要望または作業目的、確定した判断、現在の結果、未対応・保留を区別する。実装済み、設定済み、自動テスト済み、実機確認済み、本番反映済みを同じ意味で扱わない。

## 保存してはいけないもの

- APIキー、アクセストークン、Cookie、パスワード、接続文字列の値。
- メールアドレス、氏名等の個人情報。
- 合言葉、正解、秘密語、手札、投稿本文等のゲーム秘密情報。
- 内部プロンプト、ツールの生出力、長大なビルドログ、チャット全文の逐語コピー。
- 根拠のない推測、確認していない成功、存在しないコミット番号。

秘密値そのものは書かず、変数名、対象環境、設定済みかどうかだけを記録する。

## 訂正と正本への反映

- 過去ログは原則として書き換えず、誤りや方針変更は新しい項目で訂正する。
- 現行仕様が変わる場合は、ログだけでなく `DEVELOPMENT_HANDOFF.md`、ゲーム別資料、環境変数資料、登録簿、コード等の正本も同じ作業で更新する。
- ログと現行資料が食い違う場合は、現行資料とコードを優先し、差分を確認してから作業する。
- 保留事項を実装済みとして書かない。再開、撤回、完了した時点で新しい項目を追記する。
